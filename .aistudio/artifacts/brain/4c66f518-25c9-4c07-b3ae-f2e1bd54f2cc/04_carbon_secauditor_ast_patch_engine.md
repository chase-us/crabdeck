# Feature 04: Carbon SecAuditor & AST Patch Validation Engine

**Feature ID:** `FEAT-04`  
**Classification:** Security Hardening & Automated Remediation Layer  
**Security Gating:** Write (Sandbox Jail Confinement & Rollback Guard)  
**Endpoints:** `POST /claw/carbon/audit-patch`, `POST /claw/hob/sandbox-task`  
**Workspace Jail:** `vault/hob_workspace/`  

---

## 1. System Overview

The **Carbon SecAuditor & AST Patch Validation Engine** acts as an automated static security auditor and self-healing patch generator. Before any code patch generated by an LLM is accepted into the codebase, it must pass through an AST (Abstract Syntax Tree) compiler gate and a sandboxed filesystem jail.

```
Candidate Source File
       |
       v
[ Carbon SecAuditor ] ---> Scans for CWE-89 (SQLi), CWE-78 (Cmd Inj), CWE-918 (0.0.0.0 Binding)
       |
       v
[ LLM Remediation ]   ---> Synthesizes Remediated Candidate Code
       |
       v
[ AST Parse Gate ]    ---> Python ast.parse() / TypeScript ts.createSourceFile()
       |
       +---> SYNTAX ERROR? ---> [ REJECTED_INVALID_SYNTAX ] (Diff withheld, original kept)
       |
       +---> SYNTAX VALID? ---> [ CERTIFIED_AST_VALID ]
                                       |
                                       v
                             [ Hob Sandbox Confinement ]
                             Assert: realpath in workspace
                                       |
                                       v
                             [ Emit Unified Diff + HMAC-SHA256 Nonce ]
```

## 2. AST Syntax Gate & Certification Protocol

When an agent proposes a bugfix or security patch:
1. The engine invokes `ast.parse()` on the candidate code.
2. If syntax errors exist (such as missing parentheses, unterminated strings, or malformed decorators), the engine records the exact line number, column offset, and compiler error trace.
3. **Patch Withholding Invariant:** Under status `REJECTED_INVALID_SYNTAX`, the unified diff is suppressed and the pipeline rejects the change, preventing corrupted AST structures from entering production code.
4. If valid, status `CERTIFIED_AST_VALID` is returned along with a unified diff (`a/file -> b/file`).

### Audit Response Contract (`AuditPatchResponse`):
```json
{
  "file_path": "backend_py/api/query.py",
  "vulnerabilities_found": [
    {
      "cwe": "CWE-89",
      "severity": "HIGH",
      "description": "Raw string interpolation detected in SQLite execute query",
      "line_number": 42
    }
  ],
  "patch_status": "CERTIFIED_AST_VALID",
  "ast_valid": true,
  "syntax_error_details": null,
  "unified_diff": "--- a/backend_py/api/query.py\n+++ b/backend_py/api/query.py\n@@ -42,1 +42,1 @@\n-    cursor.execute(f\"SELECT * FROM users WHERE id = '{user_id}'\")\n+    cursor.execute(\"SELECT * FROM users WHERE id = ?\", (user_id,))",
  "hmac_sha256": "4a71c89e2b10df48"
}
```

## 3. Hob Sandbox Canonical Realpath Confinement

To protect the host workstation from prompt injections or malicious directory traversals:
1. The sandbox root is locked to `vault/hob_workspace/`.
2. All path operations execute `os.path.realpath`:
   ```python
   real_root = os.path.realpath(workspace_dir)
   raw_target = os.path.realpath(os.path.join(real_root, filename))
   
   if os.path.commonpath([real_root, raw_target]) != real_root or os.path.dirname(raw_target) != real_root:
       raise ValueError(f"Security Alert: Directory traversal jailbreak detected: {filename}")
   ```
3. Any attempt to write outside `vault/hob_workspace/` (e.g. `../../scripts/smoke.sh` or `../../.env`) triggers an immediate security exception, increments the threat counter, and halts agent execution.
4. For every in-bounds mutation, an atomic undo snapshot (`undo_<uuid>`) is retained in `vault/snapshots/`.

## 4. UI Playground Controls (`ASTPatchPlaygroundView.tsx`)

The interactive interface provides:
- **Preset Test Cases:** Toggle between vulnerable code examples (SQL Injection, Command Injection, Malformed Syntax, Traversal Exploit).
- **Interactive Patch Tester:** Modify code live in an editor and trigger immediate AST parsing and diff generation.
- **Visual Status Badges:** Instant emerald `CERTIFIED_AST_VALID` or crimson `REJECTED_INVALID_SYNTAX` chips.
- **Unified Diff Viewer:** Line-by-line syntax-highlighted diff display with red/green deletions and additions.

## 5. Verification & Smoke Suite Assertions

- **Assertion 56:** `run_carbon_audit_and_patch()` certifies valid patches as `CERTIFIED_AST_VALID` and rejects syntax flaws as `REJECTED_INVALID_SYNTAX`.
- **Assertion 57:** Traversal attempts (e.g. `../scripts/smoke.sh`) in `run_hob_sandbox_task()` raise `ValueError` and withhold file system writes.
